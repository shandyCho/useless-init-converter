## What's new in 0.2.2

A bug-fix release for package updates on a running s6 boot.

- **SELinux policy updates:** updating `selinux-policy-targeted` in one
  transaction with a package that has its own SELinux module (`passt-selinux`,
  `container-selinux` and others, as a large `dnf upgrade` can) restored the
  labels under `/run/service`. `init_t` could then no longer write to the fifos
  there, so every reload failed with `Permission denied` until the next boot.
  The SELinux module now labels them. Checked on a running s6 boot with
  `dnf reinstall selinux-policy-targeted passt-selinux`: the labels were restored,
  and the reload that followed succeeded with no denials.
- **`dnf` hang:** a transient service whose start fails before it runs is now
  unloaded. It used to hold the caller's output pipe, which left `dnf` waiting
  forever on a scriptlet that ran `systemctl --user -M`. This is covered by the
  test suite; the original hang wasn't reproduced on a real boot.
- **Reloads:** a reload's last failed attempt now puts back the scan directory
  links of running services, as the earlier attempts did.

After upgrading, run `sudo uinitconverter init --yes` and reboot. This also
repairs labels left by an earlier update.

**Known issues:**
- gnome-shell may still crash at shutdown. It hasn't since the order change in
  0.2.0, in at least 14 shutdowns, which is too few to call it fixed.
- gnome-shell hung for 5 s at one shutdown until it was aborted; cause unknown.
- `s6-ftrigrd` can crash during a reload that adds services, leaving a core file.
  The reload retries and recovers. This is upstream behaviour and isn't fixed here.
