## What's new in 0.3.0

The commands have new names, and systemd's user services can run under an
s6 user manager.

- **Commands renamed to `initconvert*`:** `initconvert` (was `uinitconverter`),
  `initconvertd`, `initconvert-gen`, `initconvert-runner`, `initconvert-timers`,
  and the standalone `initconvert-fdstore`, `-notify`, `-journal-relay` and
  `-linkwatch` (the standalone tools are now 0.2.0). Packages, paths, s6
  services, the SELinux module, the D-Bus interface, kernel options and
  variables keep their `uinitconverter` names. Nothing is migrated
  automatically: after upgrading, run `sudo initconvert init` from the normal
  systemd boot, as described in
  [Moving to the initconvert commands](../README-us.md#moving-to-the-initconvert-commands).
- **The s6 user manager:** the new package `uinitconverter-user` runs
  `user@UID.service` with `initconvert-user-manager` instead of
  `systemd --user`. On the s6 boot it's the default when the package is
  installed (`USER_MANAGER=systemd` keeps `systemd --user`). On a normal
  systemd boot, `sudo initconvert-user-setup on` turns it on (`off` and
  `status` too). In the GNOME test VM it runs GDM's greeter and GNOME sessions
  unmodified, including logout, a new login, a user switch, lingering users,
  the RPM update helper and reboots. If it fails a user, it hands over to
  `systemd --user` for the rest of the boot.
- **Closer to systemd:** more job modes (`replace-irreversibly`, `fail`,
  `flush`, ...), `Conflicts=`, `PartOf=`, `BindsTo=` and `StopWhenUnneeded=`
  side effects, `Accept=yes` sockets (unix, and TCP with s6-networking),
  `MAINPID=` hand-over (podman quadlets), `GetUnitByPIDFD`, and `GetAll`
  replies in systemd's order.
- **Faster stops:** a user manager stops at a reboot in about 0.7 s per user
  in the VM (`systemd --user`: about 0.5 s). It used to take several seconds,
  and up to 8-11 s with three users.
- **Fixes:** among them a start of `user@UID` that was read as failed too early,
  which in the VM left some reboots without a GNOME session; sound under the
  user manager (wireplumber wasn't started, and a pipewire restart left it
  stopped); SELinux-confined users' managers; a separate `/var` on the s6
  boot; `--default-s6` with `/boot` on a btrfs subvolume.

After upgrading, run `sudo initconvert init` from the normal systemd boot and
reboot.

**Known issues:**
- Under the s6 boot's own system manager, the s6 user manager has run in the
  test VM only, not on real hardware.
- On a systemd boot with only `uinitconverter-user` (no SELinux module), a
  confined user's manager can't write its record in
  `/run/uinitconverter-user` (one denial per start); it uses its runtime
  directory instead.
