## 0.4.0의 새로운 점

systemd와 셸을 줄였습니다. `user@UID`는 다시 `systemd --user`를 실행하고, journald와 resolved는 기본으로
꺼지며, 부팅 스크립트는 Rust가 되었고, reload는 더 이상 실행 중인 서비스를 재시작하지 않습니다.

- **s6 사용자 매니저 삭제:** `user@UID.service`는 두 부팅 모두에서 `systemd --user`를 실행합니다.
  업데이트가 `uinitconverter-user`(`uinitconverterd`가 Obsoletes)와 `initconvert-user-setup on`이 적은
  `user@` drop-in을 지웁니다. 테스트 VM의 s6 부팅에서 GNOME 세션, 로그아웃, 사용자 전환, SELinux 제한
  사용자가 이 아래에서 동작합니다.
- **journald와 resolved가 기본으로 꺼짐:** 새로 설치하면 rsyslog(또는 syslog-ng)와
  `/var/log/uinitconverter` 아래 서비스별 s6-log 디렉터리로 로그를 남기고, DNS는 NetworkManager가
  처리합니다. `initconvert init --journal=yes` / `--resolved=yes`로 다시 켭니다. 업데이트는 기존 설치의
  설정을 유지하고, `initconvert init`은 이제 두 키를 항상 적으므로 이후의 업데이트가 `--journal=no`나
  `--resolved=no`를 되돌리지 않습니다.
- **부팅에서 systemd 프로그램을 줄임:** s6 항목은 루트가 지원하지 못하는 것(LVM, MD, multipath,
  네트워크 루트, 별도의 `/usr`, `resume=`, TPM2/FIDO2/PKCS#11 LUKS 키)을 쓰지 않으면 systemd 없는
  uinitconverter의 initramfs로 부팅합니다. Fedora의 것을 유지할 때는 `initconvert init`이 이유를
  알려 줍니다. systemd-vconsole-setup, -backlight, -user-sessions, -machine-id-setup은 kbd, s6 oneshot,
  tmpfiles, `dbus-uuidgen`으로 대체했습니다.
- **셸을 Rust로:** stage 2, 종료, init-selinux, kernel-install 플러그인, initramfs 빌더와 이미지 안의
  단계, 초기 부팅 단계, 직접 작성한 s6 서비스의 `run` 스크립트가 이제 `initconvert` 하위 명령입니다
  (`initconvert`로의 링크나 한 줄짜리 execline 스크립트를 통해).
- **reload가 `daemon-reload`처럼 동작:** 서비스는 다음 `systemctl daemon-reload`까지 데이터베이스의
  유닛 파일로 실행됩니다(파일이 디스크에서 바뀌면 `systemctl status`가 경고). 실행 중인 서비스를
  재시작하게 되는 reload(s6-rc-update는 새 서비스에 대한 의존성이 생긴 서비스를 모두 재시작합니다)는
  대신 다음 부팅용으로 설치하고 그렇다고 알립니다("not applied to the running system: the update would
  restart ..."). 아무것도 재시작하지 않는 reload는 그대로 라이브로 적용됩니다.
- **수정:** 0.3.0에서 업데이트한 뒤 로그인이 막히던 문제(남은 `/run/nologin`), s6 부팅에서 업데이트하면
  시스템 매니저가 멈출 수 있던 문제(dbus와 initconvertd가 그 아래에서 재시작됨), reload 중의 D-Bus
  활성화가 이전 데이터베이스에서 서비스를 시작하던 문제, 아직 실행 중인 데이터베이스에 없는 유닛의 오류
  메시지.
- **삭제:** 어떤 프로그램도 부르지 않는 D-Bus 메서드(`AbandonScope`, `GetJob`, `UnrefUnit`, `Unit`
  인터페이스의 `TryRestart`, `ReloadOrRestart`, `ReloadOrTryRestart`).

업그레이드한 뒤 README의 "업데이트"대로 `sudo initconvert init --yes`를 실행하고 재부팅하세요. 독립
도구는 0.2.0 그대로입니다.

**알려진 문제:**
- 미뤄진 reload 뒤에는 새 데이터베이스에만 있는 유닛을 다음 부팅까지 시작할 수 없고, 이후의 reload도
  모두 미뤄집니다. 시작할 때의 오류가 그렇게 알려 줍니다.
- 라이브로 적용되는 reload는 재시작하거나 지우는 서비스에 대해 `s6-supervise: fatal: unable to chdir to
  NAME`을 로그에 남길 수 있고, s6 2.15.1.1의 s6-ftrigrd가 업데이트 중에 가끔 죽습니다. gen이 서비스를
  다시 연결하고 재시도합니다. 둘 다 업스트림 동작이며 시스템은 계속 동작합니다.
