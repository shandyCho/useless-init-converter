## What's new in 0.4.0

Less systemd and less shell: `user@UID` runs `systemd --user` again,
journald and resolved are off by default, the boot's scripts are Rust, and a
reload no longer restarts running services.

- **The s6 user manager is removed:** `user@UID.service` runs
  `systemd --user` on both boots. The update removes `uinitconverter-user`
  (`uinitconverterd` Obsoletes it) and the `user@` drop-in that
  `initconvert-user-setup on` wrote. In the test VM, GNOME sessions, logout,
  user switching and SELinux-confined users work under it on the s6 boot.
- **journald and resolved off by default:** a new install logs through
  rsyslog (or syslog-ng) and one s6-log directory per service under
  `/var/log/uinitconverter`, and NetworkManager handles DNS.
  `initconvert init --journal=yes` / `--resolved=yes` turn them back on. An
  update keeps an existing install's setting, and `initconvert init` now
  always writes both keys, so a later update never undoes `--journal=no` or
  `--resolved=no`.
- **Fewer systemd programs at boot:** the s6 entry boots uinitconverter's
  own initramfs without systemd unless the root needs what it can't do (LVM,
  MD, multipath, a network root, a separate `/usr`, `resume=`, a TPM2/FIDO2/PKCS#11
  LUKS key); `initconvert init` says why when it keeps Fedora's.
  systemd-vconsole-setup, -backlight, -user-sessions and -machine-id-setup
  are replaced by kbd, s6 oneshots, tmpfiles and `dbus-uuidgen`.
- **Shell replaced by Rust:** stage 2, the shutdown, init-selinux, the
  kernel-install plugin, the initramfs builder and its in-image steps, the
  early-boot steps and the hand-written s6 services' `run` scripts are now
  `initconvert` subcommands (through links to it or one-line execline
  scripts).
- **Reloads behave like `daemon-reload`:** services run the unit files of
  their database until the next `systemctl daemon-reload` (`systemctl
  status` warns when a file changed on disk). A reload that would restart a
  running service (s6-rc-update restarts every service that gains a
  dependency on a new one) is installed for the next boot instead, and says
  so: "not applied to the running system: the update would restart ...".
  Reloads that restart nothing still apply live.
- **Fixes:** logins locked out after the update from 0.3.0 (`/run/nologin`
  left behind); an update on the s6 boot that could hang the system manager
  (dbus and initconvertd restarted under it); a D-Bus activation during a
  reload that started the service in the old database; a clearer error for a
  unit that isn't in the running database yet.
- **Removed:** D-Bus methods no program calls (`AbandonScope`, `GetJob`,
  `UnrefUnit`, the `Unit` interface's `TryRestart`, `ReloadOrRestart`,
  `ReloadOrTryRestart`).

After upgrading, run `sudo initconvert init --yes` and reboot, as in the
README's "Update". The standalone tools stay at 0.2.0.

**Known issues:**
- After a reload that was held back, a unit that only the new database has
  can't be started until the next boot, and every later reload is held back
  too. The start's error says so.
- Reloads that apply live may log `s6-supervise: fatal: unable to chdir to
  NAME` for services they restart or remove, and s6 2.15.1.1's s6-ftrigrd
  sometimes crashes during the update; gen relinks the services and
  retries. Both are upstream behaviour; the system keeps running.
