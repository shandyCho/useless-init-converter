## 0.3.0의 새로운 점

명령 이름이 바뀌었고, systemd의 사용자 서비스를 s6 사용자 매니저에서 실행할 수 있습니다.

- **명령 이름이 `initconvert*`로 바뀜:** `initconvert`(이전 `uinitconverter`), `initconvertd`,
  `initconvert-gen`, `initconvert-runner`, `initconvert-timers`, 그리고 독립 도구 `initconvert-fdstore`,
  `-notify`, `-journal-relay`, `-linkwatch`(독립 도구는 이제 0.2.0). 패키지, 경로, s6 서비스, SELinux 모듈,
  D-Bus 인터페이스, 커널 옵션과 변수는 `uinitconverter` 이름을 그대로 씁니다. 자동 이전은 없습니다.
  업그레이드한 뒤 일반 systemd 부팅에서 `sudo initconvert init`을 실행하세요.
  [initconvert 명령으로 이전하기](../README.md#initconvert-명령으로-이전하기)에 설명이 있습니다.
- **s6 사용자 매니저:** 새 패키지 `uinitconverter-user`가 `user@UID.service`를 `systemd --user` 대신
  `initconvert-user-manager`로 실행합니다. s6 부팅에서는 이 패키지가 설치되어 있으면 기본값입니다
  (`USER_MANAGER=systemd`이면 `systemd --user`를 유지). 일반 systemd 부팅에서는
  `sudo initconvert-user-setup on`으로 켭니다(`off`, `status`도 있음). GNOME 테스트 VM에서 GDM의 그리터와
  GNOME 세션을 수정 없이 실행합니다. 로그아웃, 새 로그인, 사용자 전환, linger 사용자, RPM 업데이트 도우미,
  재부팅도 포함됩니다. 어떤 사용자에서 실패하면 그 부팅이 끝날 때까지 `systemd --user`에 넘깁니다.
- **systemd에 더 가까워짐:** 작업 모드 추가(`replace-irreversibly`, `fail`, `flush`, ...),
  `Conflicts=`, `PartOf=`, `BindsTo=`, `StopWhenUnneeded=`의 부수 효과, `Accept=yes` 소켓(unix, 그리고
  s6-networking이 있으면 TCP), `MAINPID=` 넘김(podman quadlet), `GetUnitByPIDFD`, systemd 순서의
  `GetAll` 응답.
- **더 빠른 정지:** VM에서 재부팅할 때 사용자 매니저가 사용자당 약 0.7초에 멈춥니다(`systemd --user`:
  약 0.5초). 이전에는 몇 초가 걸렸고, 사용자가 셋이면 8-11초까지 걸렸습니다.
- **수정:** 그중에는 `user@UID`의 시작을 너무 일찍 실패로 읽던 문제(VM에서 일부 재부팅에 GNOME 세션이
  없었음), 사용자 매니저에서의 소리(wireplumber가 시작되지 않았고, pipewire 재시작이 그것을 멈춘 채로
  남김), SELinux로 제한된 사용자의 매니저, s6 부팅에서 따로 있는 `/var`, `/boot`가 btrfs 하위 볼륨일 때의
  `--default-s6`이 있습니다.

업그레이드한 뒤 일반 systemd 부팅에서 `sudo initconvert init`을 실행하고 재부팅하세요.

**알려진 문제:**
- s6 부팅 자체의 시스템 매니저 아래에서 s6 사용자 매니저는 테스트 VM에서만 실행해 봤고, 실제 하드웨어에서는
  아직입니다.
- `uinitconverter-user`만 있는(SELinux 모듈 없는) systemd 부팅에서는 제한된 사용자의 매니저가
  `/run/uinitconverter-user`에 기록을 쓰지 못합니다(시작할 때마다 거부 한 번). 대신 런타임 디렉터리를 씁니다.
